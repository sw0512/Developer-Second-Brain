# Hooks (v0.4.2)

훅은 두 개이고, 방향이 반대입니다.

| 훅 | 이벤트 | 하는 일 |
|---|---|---|
| `detect-on-edit.sh` | `PostToolUse` | 작업이 끝났을 만한 시점에 **모델에게 판단을 요청**한다 (제안 경로) |
| `guard-vault-write.sh` | `PreToolUse` | 승인 없이 볼트에 새 문서가 생기는 것을 **거부**한다 (강제 경로) |

**제안까지만 자동화하고, 저장은 여전히 사용자 승인이 필요합니다.** 아래 절반은 제안 경로,
[볼트 쓰기 가드](#볼트-쓰기-가드-guard-vault-writesh) 이후가 강제 경로입니다. 둘은 **함께
설치됩니다** — 제안 경로만 깔면 강제하는 게 없는 상태고, 그게 2026-08-04에 실제로 터진 구성입니다.

## 왜 필요했나

판단 규칙(`references/`)은 다 있었는데 **제안이 거의 뜨지 않았습니다.**

스킬은 **모델이 스스로 켜는 것**이고, 그 방아쇠는 스킬 설명(description)입니다. 그런데 이
스킬의 발동 조건은 "개발 문제를 **다 풀고 난 뒤에** 쓰세요"예요. 이건 사용자 요청에 매핑되는
조건이 아닙니다. 요청이 없는 상태에서 모델이 *자발적으로* "이제 기록 가치를 판단해볼까?" 하고
떠올려야 하는데, **그걸 시켜주는 게 아무것도 없었습니다.** 엔진은 멀쩡한데 시동 장치가 없던
셈이고, 그래서 `/document`로 직접 부를 때만 동작했습니다.

## v0.4가 실패한 이유 (그리고 v0.4.1이 다른 이유)

v0.4는 **Stop 훅**에서 `decision: block` + `reason`으로 모델을 호출했습니다. 동작은 했는데
**쓸 수가 없었습니다.**

Claude Code는 차단된 Stop의 `reason`을 **사용자 화면에 렌더링합니다.** 그래서 "조용히 넘어가라,
훅이 돌았다는 말도 하지 마라"는 지시문 자체가 매 발동마다 화면에 에러처럼 찍혔습니다.
**침묵 경로가 애초에 존재하지 않았습니다.**

이건 튜닝으로 못 고칩니다. 구조적인 문제예요 — `Stop`은 Claude Code의 `hookSpecificOutput`
union 멤버가 아니라서 `additionalContext`(사용자를 거치지 않고 모델에만 닿는 채널)를 쓸 수
없습니다. **`PostToolUse`는 멤버입니다.** 그래서 이벤트를 바꿨습니다.

| | v0.4 (폐기) | v0.4.1 |
|---|---|---|
| 이벤트 | `Stop` | `PostToolUse` (`Edit\|Write\|NotebookEdit`) |
| 채널 | `decision: block` + `reason` | `hookSpecificOutput.additionalContext` |
| 사용자 노출 | **매번 노출됨** | 없음 |
| 쿨다운 기준 | `session_id` | **프로젝트 경로 + 시간** |

## 구성

| 파일 | 역할 |
|------|------|
| `detect-on-edit.sh` | 탐지 훅 본체. 값싼 게이트 → 통과 시 모델에게 조용히 판단을 요청 |
| `guard-vault-write.sh` | 승인 게이트 본체. 제안되지 않은 새 볼트 문서의 쓰기를 거부 |
| `hooks.json` | 플러그인 설치용 훅 등록 (`${CLAUDE_PLUGIN_ROOT}` 사용) |

심링크 개발 설치는 `hooks.json`을 읽을 플러그인 매니페스트가 없어서, `scripts/install-dev.sh`가
`scripts/hook-wiring.py`로 `~/.claude/settings.json`에 직접 등록합니다. 이 스크립트는 v0.4
Stop 훅 잔재도 함께 제거합니다.

## 동작

```
파일 편집 (Edit / Write / NotebookEdit)
   │
   ▼
쿨다운 확인  ← 이미 걸려 있으면 stat 한 번으로 즉시 종료
   │
   ▼
값싼 게이트  ← "판단할 가치가 있나?" 만 판정
   │  편집 ≥3, 그리고 메시지 ≥12개
   ▼
additionalContext 주입 (사용자에게 안 보임)
   │
   ▼
모델이 작업 마무리 시점에 references/ 규칙으로 판단  ← "기록할 가치가 있나?" 는 여기서만
   │
   ▼
가치 있으면 → "기록할까요?" 제안 / 아니면 아무 말 없이 종료
```

### 역할 분리가 핵심

훅은 **기록 가치를 절대 판단하지 않습니다.** "작업이 실제로 일어났나?"만 봅니다. 가치 판단은
`references/`에 단 하나로 남아야 하고, 훅이 그걸 흉내내면 규칙이 두 군데로 갈라집니다.

그래서 주입되는 지시문에 못박아뒀습니다 — *"이 알림은 활동이 있었다는 것만 보고한다. 가치
판단이 아니며 `should_document`의 근거로 쓰면 안 된다. 침묵이 정상이고 가장 흔한 결과다."*

## 임계값

`detect-on-edit.sh` 상단에 상수로 모여 있습니다.

| 상수 | 값 | 의미 · 정한 이유 |
|------|-----|------------------|
| `MIN_EDITS` | 3 | 편집 횟수. v0.4의 1에서 올림 — `PostToolUse`는 편집마다 돌기 때문에 스쳐가는 편집 하나로 무장되면 안 됨 |
| `MIN_MESSAGES` | 12 | 너무 짧은 대화(한 줄 수정, 중단된 시작)를 걸러냄 |
| `COOLDOWN_HOURS` | 6 | 같은 프로젝트에서 다시 무장되기까지의 간격 |

전부 **실사용 데이터 없이 눈으로 정한 값**입니다. 진짜 판단은 엔진이 하므로 이 게이트는
"개발 작업이 아예 없는 세션"만 거르면 됩니다. `MIN_EDITS`와 `MIN_MESSAGES`는 **AND**입니다.

### 쿨다운을 세션이 아니라 프로젝트로 잡은 이유

v0.4는 `session_id`로 잡았고 그게 두 번째 결함이었습니다. **한 덩어리의 작업이 여러 세션에
걸쳐 있으면** — 백그라운드 잡과 인터랙티브 세션은 서로 다른 `session_id`입니다 — "세션당 1회"가
지켜져도 사용자 체감으로는 반복입니다. 실제로 마커에 UUID가 2개 찍혔습니다.

사용자가 체감하는 단위는 "지금 이 프로젝트"이므로, 마커를 **cwd 해시**로 잡고 시간으로
만료시킵니다. 같은 디렉터리에서 일하는 모든 세션이 하나를 공유합니다.

### 트랜스크립트를 읽는 방식

- **줄 수가 아니라 메시지 수를 셉니다.** JSONL에는 스냅샷·훅 기록·첨부 같은 관리용 줄이 섞여
  있습니다. 실제 세션에서 **564줄 vs 실제 메시지 309개** 였습니다.
- **슬럽하지 않고 스트리밍합니다.** `jq -s`는 149MB 트랜스크립트에서 **RSS 516MB**가 나왔습니다.
  줄 단위로 흘려보내면 **3.3MB**로 평평합니다. 편집마다 도는 훅이라 v0.4보다 훨씬 중요해졌습니다.
- 메시지의 `content`가 **문자열**인 경우도 있습니다(실제 세션에 13건). 툴 추출은 건너뛰고
  메시지 수에는 포함합니다.
- **쿨다운을 트랜스크립트 스캔보다 먼저 확인**합니다. 무장된 뒤의 편집은 `stat` 한 번(0.05초)만
  씁니다. 무장 전 전체 스캔은 2MB 기준 0.08초.

## 안전장치

지식 기록 도구가 사용자 세션을 망가뜨리면 안 됩니다. 그래서 **예상 못 한 모든 상황에서 조용히
exit 0** 합니다.

- **사용자 노출 채널을 절대 안 씀** — `decision` / `reason` / `systemMessage`를 내보내지
  않습니다. 테스트로 강제합니다(v0.4가 죽은 지점이라 설계 의도가 아니라 단언입니다).
- **stderr 억제** — 입력이 깨져도 에러가 사용자 터미널에 새지 않습니다.
- **jq 없으면 침묵** — 추측하지 않고 그냥 빠집니다.
- **마커 30일 정리** — 프로젝트당 파일 1개가 영구히 쌓이지 않도록.

## 볼트 쓰기 가드 (`guard-vault-write.sh`)

여기부터는 강제 경로입니다. 위의 탐지 훅이 *제안을 뜨게* 하는 장치라면, 이건 *제안 없이는 못
쓰게* 하는 장치입니다.

### 왜 필요했나

`PROJECT_PRINCIPLES.md` §3.2는 "사용자 승인 없이 절대 자동 저장하지 않는다"를 hard line으로
선언하는데, **그걸 강제하는 코드가 한 줄도 없었습니다.** `SKILL.md` 4단계가 모델에게 "제안하고
기다려라"라고 말할 뿐이었습니다.

2026-08-04 실제 세션에서 그대로 터졌습니다. 모델이 "기록하겠습니다" 한 줄을 출력한 **같은 턴에**
곧바로 `Write`를 호출했습니다. 막아준 건 이 시스템이 아니라 Claude Code의 권한 프롬프트였고,
`--dangerously-skip-permissions` 상태였으면 볼트에 문서가 그냥 생겼을 겁니다.

### 규칙

> **대상 파일명이, 마지막 실제 사용자 턴보다 앞선 assistant 텍스트에 등장해야 통과.**

성질 두 개가 이 규칙을 지탱합니다.

1. **언어에 의존하지 않습니다.** "기록할까요?" 같은 한국어 문구를 앵커로 잡으면 모델이 문장을
   바꿔 쓰는 순간 깨지고, 제안 포맷이 두 군데 살게 됩니다. 파일명은 제안 블록의 `저장 위치`
   줄에 어차피 들어가는 데이터입니다.
2. **모델이 위조할 수 없습니다.** 모델은 아무 텍스트나 출력할 수 있지만 **자기 출력 뒤에
   사용자 턴을 만들어낼 수는 없습니다.** 게이트 전체가 그 순서 제약 하나 위에 서 있습니다.

### 통과 근거로 안 쳐주는 것

| 모양 | 왜 아닌가 |
|---|---|
| assistant의 **tool input** | 거절당한 `Write`가 다음 시도의 통과 근거가 되어 가드가 평생 한 번만 발동함 |
| `tool_result` | role은 `user`지만 사람이 아니라 하네스가 말한 것 |
| **서브에이전트의 사용자 턴** (`isSidechain`) | 이 대화의 사용자가 아님 |
| `[Request interrupted by user]` | **거절이 승인으로 뒤집히는 경로.** Esc를 눌러 쓰기를 끊으면 평범한 user 텍스트 블록이 남고, 모양만으로는 "네 저장해줘"와 구별되지 않음 |
| `<command-name>` / `<local-command-stdout>` 등 슬래시 명령 기록, `isMeta` 주입 노트, `<system-reminder>` | 전부 하네스가 쓴 텍스트 |

마지막 두 줄은 **엔트리를 버리는 게 아니라 하네스 텍스트만 벗겨내고** 사람의 말이 남았는지
봅니다. 슬래시 명령과 함께 친 진짜 프롬프트는 **같은 엔트리**에 담겨 오기 때문에, 엔트리째
버리면 진짜 승인을 잃습니다.

### 범위와 실패 자세

- **신규 파일만.** 기존 파일 편집은 통과 — `SKILL.md` 6단계 자체 검토가 방금 쓴 파일을 같은
  턴에 고치므로, 안 그러면 문서화된 워크플로가 못 돕니다.
- **볼트 밖은 무관심.** `SECOND_BRAIN_VAULT`(기본 `~/DeveloperSecondBrain`) 아래가 아니면 즉시 빠집니다.
- **fail-open.** 예상 못 한 조건은 전부 exit 0 = "의견 없음"이고, Claude Code의 평소 권한
  프롬프트로 되돌아갑니다. jq가 없다고 볼트를 못 쓰게 되는 게 더 나쁜 버그입니다. **이 가드는
  바닥을 올릴 뿐 최후 방어선이 아닙니다.**
- **차단 사유는 모델에게만 갑니다.** `permissionDecisionReason`은 사용자 화면에 렌더링되지
  않습니다(탐지 훅과 같은 계약). 모델은 4단계로 돌아가 경로를 포함한 제안을 다시 띄웁니다.

### 감수하기로 한 마찰

실제 트랜스크립트로 되감아 검증했더니 볼트 쓰기 5건 중 3건이 차단됐고, 그중 2건은 **사용자가
경로를 못 본 채 승인한 일괄 저장**이었습니다. 완화안(같은 턴 추가 쓰기 허용)은 "승인 하나가
안 보여준 파일들의 통행증이 되는" 구멍을 열기 때문에 채택하지 않았습니다 — 그게 정확히 이 훅이
막으려고 만들어진 실패 모양입니다. 모델이 경로를 한 줄 복창하면 전부 통과합니다.

전체 근거·리플레이 방법·후보 비교는 볼트 ADR
`adr/2026-08-07-vault-write-guard-strict-approval-rule.md`에 있습니다.

## 끄기

```bash
export SECOND_BRAIN_HOOK_DISABLED=1    # 탐지(제안)만 비활성화
export SECOND_BRAIN_GUARD_DISABLED=1   # 승인 게이트만 비활성화
./scripts/install-dev.sh --no-hook     # 설치할 때 훅만 제외
./scripts/uninstall-dev.sh             # settings.json에서 제거
```

두 스위치는 **일부러 분리돼 있습니다.** 제안을 끄고 싶은 것과 승인 게이트를 끄고 싶은 것은 다른
요구입니다. 하나로 합치면 "알림 그만"이 게이트 해제로 번집니다.

## 테스트

```bash
./tests/hook-gate.sh           # 탐지 훅 — 게이트 판정 + 출력 채널 계약
./tests/vault-write-guard.sh   # 승인 게이트 — 규칙 + fail-open + 출력 채널 계약
```

`tests/fixtures/`가 *엔진의 판단*을 검증한다면, 이 둘은 그 아래 계층인 *훅의 동작*을 검증합니다.
가드 쪽 케이스는 대부분 **차단**입니다 — 잘못된 통과는 사용자가 동의한 적 없는 문서를 남기지만,
잘못된 차단은 턴 하나를 더 쓸 뿐이기 때문입니다. 마지막 절은 가드를 만들게 한 2026-08-04 세션을
손으로 재구성해 리플레이합니다(실제 트랜스크립트는 개인 내용이라 커밋하지 않습니다).

## 상태 파일

프로젝트당 쿨다운 마커가 쌓입니다.

- 기본값: `~/.claude/second-brain-state/`
- 변경: 환경변수 `SECOND_BRAIN_STATE_DIR`

빈 파일이고 30일 지난 것은 자동 정리됩니다. 수동으로 지워도 안전합니다(해당 프로젝트에서
쿨다운이 즉시 풀릴 뿐입니다).
